# Project Workflow — Lumeo Campaign Studio

> **Purpose.** This document is the engineering workflow log for Lumeo Campaign
> Studio. It records *what* shipped, *why* the decisions were made, and *how*
> the build progressed phase by phase.
>
> If you are evaluating the project, read this document **after** `README.md`
> for setup and feature context. If you are extending the project, treat this
> file as the single source of truth on architectural decisions and design
> rationale — code wins on conflicts; this file wins on intent.

---

## 1. Snapshot (final state)

Lumeo Campaign Studio is an AI-assisted campaign management platform that
takes a free-form marketing brief, surfaces gaps, asks targeted clarifying
questions, generates a multi-channel execution plan with copy drafts and a
dependency-aware timeline, audits it with an LLM Critic and four
deterministic governance scanners, and ships a reviewable plan with a citable
Assumption Ledger.

Three workflows on one platform:

1. **Plan from Brief (W1)** — paste brief → clarify → plan → review → approve.
2. **Brief QA (W2)** — paste any brief or plan → audit it.
3. **Asset Consistency (W3)** — drop in 3+ marketing assets → cluster
   terminology, recommend canonical CTAs.

All thirteen build phases (P0 → P12) are complete. Test surface: **188 unit
tests + 9 integration tests** passing. Ten Architecture Decision Records
(ADRs) documented below.

## 3. Architecture Decision Records (ADRs)

Each ADR is numbered, dated, and immutable. New decisions append; reversed
decisions are marked superseded — never deleted.

### ADR-001 — Stack: LangGraph + FastAPI + Streamlit + Azure OpenAI + Postgres + Qdrant + Redis
**Decision.** Build on LangGraph as orchestrator, FastAPI backend, Streamlit
UI, Azure OpenAI for LLM/embeddings, Postgres for structured + JSONB, Qdrant
for vectors, Redis for cache + dialog state.
**Why.** LangGraph gives typed state across nodes, native HITL interrupts,
and checkpoint-and-resume — the right shape for a multi-agent HITL system.
FastAPI is async-native (parallel agent fan-out). Streamlit is the fastest
path to multi-page UI for hackathon scope. The three storage services were
already in the provided docker-compose, so no infra burden.
**Alternatives considered.** CrewAI (rejected: agent-to-agent chatter
overhead at runtime); AutoGen (rejected: GroupChat burns tokens with
unpredictable demo latency); custom async orchestration (rejected: would
re-invent interrupt + checkpoint).
**Date.** 2026-04-26 · **Status.** Accepted

### ADR-002 — Single in-process orchestrator
**Decision.** Run the LangGraph orchestrator inside the FastAPI process. No
separate worker container.
**Why.** SSE-streamed responses + LangGraph's async execution handle the
≤90 s end-to-end latency budget. Extracting to a worker is a clean
post-demo refactor.
**Date.** 2026-04-26 · **Status.** Accepted

### ADR-003 — Channel cap = 3
**Decision.** Cap parallel channel fan-out at 3 channels (LinkedIn, Email,
Paid Search by default).
**Why.** Latency budget is tight; 3 parallel LLM calls hit ~6 s, 6 parallel
calls risk Azure rate-limit thrash. Three channels also keeps the plan
visually scannable in the UI. The seeded catalog has 6 channels available;
the cap is enforced in the planner.
**Date.** 2026-04-26 · **Status.** Accepted

### ADR-004 — Minimal D3 (terminology + CTA only)
**Decision.** W3 (multi-channel consistency) ships with terminology
clustering + CTA scanning + canonical resolver. Tone drift, audience
framing, and the full report composer are deferred.
**Why.** Tone drift requires a fingerprint quality bar that's risky to hit
in a hackathon timeline. Terminology + CTA give the cinematic
"AI-powered (×3) vs AI-assisted (×2) — canonical is AI-assisted" demo
moment with high reliability.
**Date.** 2026-04-26 · **Status.** Accepted

### ADR-005 — Eval harness baked in from P2
**Decision.** `eval/runner.py` skeleton + `eval/golden_set.py` loader land
in P2 alongside the LLM gateway, not at the end.
**Why.** Regression detection must be cheap from the moment the first agent
runs. If we wait until P9, prompt regressions during P3–P8 are invisible.
**Date.** 2026-04-26 · **Status.** Accepted

### ADR-006 — Greedy cosine clustering replaces HDBSCAN for W3 terminology
**Decision.** `agents/terminology_scanner.py:cluster_terms` uses greedy
single-pass cosine-threshold clustering (τ=0.70) over Azure
`text-embedding-3-small-alpha` vectors instead of HDBSCAN. The API surface
is preserved so swapping back to HDBSCAN later is a one-file change.
**Why.** No native-build risk on Windows/WSL; deterministic on the demo
asset set; the plan's own fallback already authorizes pairwise-similarity
for `len(assets) < 3`. Threshold 0.70 was chosen empirically — live cosine
values on the small embedding model are AI-powered ↔ AI-assisted = 0.7515,
book-a-demo ↔ schedule-a-call = 0.6172, all unrelated pairs ≤ 0.41.
**Date.** 2026-04-29 · **Status.** Accepted

### ADR-007 — Light production palette (UI overhaul)
**Decision.** Replace the original demo palette with a light production
palette: canvas `#F6F7FB`, panel `#FFFFFF`, indigo accent `#4F46E5`,
mint `#0EA5E9`, slate-900 text. Single global fixed dark header bar
emitting `Lumeo | Campaign Studio` wordmark on every page.
**Why.** Light palette reads as production tooling rather than a demo
prototype. Indigo on near-white matches the visual language of Linear /
Stripe / Vercel.
**Date.** 2026-05-03 · **Status.** Accepted

### ADR-008 — Override apply: list/object-typed paths route to `mandatory_inclusions` audit
**Decision.** Any free-text override whose `field_path` targets a
list/dict/tuple/set-typed top-level Brief field (`quantified_targets`,
`success_metrics`, etc.) is routed to `constraints.mandatory_inclusions` as
`[override:{path}] {value}` audit line. The endpoint
`POST /briefs/{id}/overrides` wraps `apply_overrides_to_brief` and any
residual `ValidationError` is returned as a structured 422 — never 500.
**Why.** The Clarifier sometimes emits paths like `quantified_targets` when
asking about a metric/baseline/target. The user's free-text answer cannot
validly populate `list[QuantifiedTarget]`. Routing those to the audit bucket
preserves the answer, keeps the Brief shape valid, and lets the rest of the
user's overrides apply.
**Date.** 2026-04-30 · **Status.** Accepted

### ADR-009 — Extraction-schema pattern for LLM-bound schemas
**Decision.** Every Pydantic schema bound to an Azure OpenAI structured
output that has auto-generated fields (UUID, datetime) gets a sibling
`XxxExtraction` schema with those fields *dropped*. The agent calls
`call_structured(output_schema=XxxExtraction)` and promotes via
`to_brief()` / `to_gaps()` / etc. Server fills `id` / `created_at` after
the LLM returns.
**Why.** `core/llm/structured.py:_strictify` force-overwrites `required`
to include every property (Azure strict-mode demands it). The LLM is then
forced to emit every field, including server-generated UUIDs, which it can
only emit as `null`, which 400s on Pydantic validation.
**Date.** 2026-04-27 · **Status.** Accepted

### ADR-010 — PDF (reportlab) + PPTX (python-pptx) replace JSON in the UI export row
**Decision.** The UI Export section surfaces three buttons — **HTML**,
**PDF**, **PPTX**. JSON and Markdown remain on the API surface
(`GET /plans/{id}/export/{json,markdown}`) for tooling but are not
exposed to the Streamlit user.
**Why.** Marketers want a shareable artifact, not a JSON dump. Both
libraries are pure Python (no system deps). reportlab Platypus + python-pptx
mirror the Markdown structure, so we don't maintain a separate plan model.
**Alternatives considered.** weasyprint (rejected: Pango / Cairo system
deps); xhtml2pdf (rejected: weaker HTML/CSS support, dated output);
wkhtmltopdf via pdfkit (rejected: external binary + license uncertainty).
**Date.** 2026-05-04 · **Status.** Accepted

## 4. Implementation Notes

Operational gotchas, workarounds, and lessons learned. Organized by topic,
not chronological.

### LLM Gateway
- Structured outputs use
  `response_format={"type":"json_schema", "json_schema":{strict:True}}`.
  Strict mode requires `additionalProperties:false` on every object and
  `required` listing all properties; `core/llm/structured.py:_strictify`
  enforces both before sending.
- Cache key: `sha256(prompt_name + prompt_version + variables_json + schema_name)`.
  Bumping the prompt to v2 invalidates all v1 cache entries automatically —
  no manual flush needed.
- Repair path: on first `ValidationError`, the gateway re-renders the
  prompt with a "your previous response failed schema validation: …"
  addendum and retries once at temperature 0. Two consecutive parse
  failures raise `StructuredOutputParseError`.
- Tenacity retry covers `TimeoutError` and `ConnectionError` only — auth
  and 4xx errors fail fast.
- `_try_add_cost` re-raises `BudgetExceeded` (callers must know) but
  swallows Redis errors so a Redis hiccup doesn't kill a paid Azure call.

### Orchestrator
- `MAX_REVISIONS = 2` is enforced in `orchestrator/nodes.py` (in code, not
  in the prompt). Never raise above 2 — it would risk a runaway loop.
- `CampaignState` is `extra='forbid'`. Side-channel data (copy drafts,
  dialog state, demo payloads) lives in Redis under namespaced keys:
  `copy_drafts:{sid}:{pid}`, `dialog:{sid}`, `demo:c:payload`,
  `demo:d:payload`. Never add transient runtime fields to `CampaignState`.

### Brief overrides (ADR-008 safety net)
- `Brief.raw_source` is immutable. Overrides go through
  `orchestrator/interrupts.py:apply_overrides_to_brief` + `BriefOverride`
  rows. `briefs.parsed_json` IS rewritten via SQLAlchemy `flag_modified`
  after `apply_overrides_to_brief` — that's the enriched view downstream
  agents read.
- The audit prefix `[override:field.path]` is scrubbed from the rendered
  surface only via `ui.styles.scrub_override_prefix(text)` — never write
  the scrubbed form back to storage.

### Brand voice
- Loaded via `knowledge/brand_voice.py:get_or_build_fingerprint(db, brand_name)`.
  Auto-builds from `seeds/brand_voice_samples/{brand_lc}_on_voice.txt` and
  `_off_voice.txt` on first call. File naming MUST be lowercase brand name.
- When unavailable, `agents/copy_drafter.py` sets
  `voice_score_breakdown={"fingerprint_available": 0.0}` so the UI shows
  "🟠 fingerprint missing" instead of pretending 0/100 is real.

### Copy drafts
- `CopyDraft.angle` is required-with-default (`"outcome-led"`). UI must
  never render `?` — schema default + `_resolve_angle` keyword fallback
  (urgency / proof / enterprise / ROI / speed / pain / benefit) guarantee
  a non-empty value.
- All copy bodies pass through `agents/copy_drafter.py:_sanitize_body`
  server-side. UI page 1 renders bodies via an HTML `<pre
  class='lumeo-copy-pre'>` inside `lumeo-copy-frame` — NOT a disabled
  `st.text_area`.

### Cost meter
- `observability/cost_meter.py:get_cost_snapshot` SUMs
  `trace_events.cost_usd` (the authoritative ledger). Falls back to
  `sessions.cost_usd` only when events sum to zero. Cache hits land at $0
  in trace (correct — they didn't cost anything).

### Vector store
- Use `client.query_points(...).points` (qdrant-client ≥ 1.10 removed
  `client.search`). The wrapper at `core/embeddings/qdrant_store.py`
  already handles both call patterns.
- All four collections use cosine distance and 1536-dim. Switching the
  embedding deployment requires `EMBEDDING_DIM` change AND recreating
  the four collections (`python scripts/seed_db.py --recreate-qdrant`).

### Observability
- `observability/trace.py:log_event` swallows exceptions; preserve that
  contract. Observability must never crash a real call.

### Governance scanners
- All four scanners (`agents/governance.py`) are deterministic. They must
  NEVER make LLM calls. This invariant is what makes the alignment-penalty
  math reproducible.

### W3 cosine threshold
- τ = 0.70 (ADR-006). Replacing with HDBSCAN requires reverting that ADR.

## 6. Conventions

How to extend or maintain this project consistently.

1. **Update this file after any architectural change.** New ADR, new
   blocker, blocker resolved, phase complete, assumption verified — log it.
2. **Timestamp everything in ISO format** (`YYYY-MM-DD`).
3. **Number ADRs sequentially** (ADR-001, ADR-002, …). Never reuse a
   number, even for superseded decisions.
4. **The Stack & Infrastructure section is the single source of truth.**
   Code drift from this section is a bug, not a flexibility.
5. **Do not delete log entries.** If something is wrong, append a
   correction with a new timestamp. The history matters for evaluation.
6. **Honor the architectural invariants in `AGENT.md` § "Architectural
   invariants — do not break"** when extending the codebase.

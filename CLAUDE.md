## Architecture Decision Records (ADRs)

> Each ADR: numbered · dated · decision · why · alternatives considered · who ratified.
> Write new ADRs as they're made. Never delete; mark superseded if reversed.

### ADR-001 — Stack: LangGraph + FastAPI + Streamlit + Azure OpenAI + Postgres + Qdrant + Redis
**Decision:** Build on LangGraph as orchestrator with FastAPI backend, Streamlit UI, Azure OpenAI for LLM/embeddings, Postgres for structured + JSONB, Qdrant for vectors, Redis for cache + dialog state.
**Why:** LangGraph gives typed state across nodes, native HITL interrupts, and checkpoint+resume — exactly what a multi-agent HITL system needs. FastAPI is async-native (parallel agent fan-out). Streamlit is the fastest path to multi-page UI for hackathon scope. The 3 storage services are already in the provided docker-compose, so no infra burden.
**Alternatives considered:** CrewAI (rejected: agent-to-agent conversation overhead at runtime, less control); AutoGen (rejected: GroupChat burns tokens, unpredictable demo latency); custom async orchestration (rejected: would re-invent interrupt + checkpoint). Next.js for UI (rejected: front-end build step costs day 1).
**Date:** 2026-04-26
**Status:** accepted

### ADR-002 — Single in-process orchestrator for hackathon (extract worker post-demo)
**Decision:** Run the LangGraph orchestrator inside the FastAPI process for Tier 0. Do not spin up a separate worker container for agent execution.
**Why:** Hackathon week is the wrong time to add infrastructure. SSE-streamed responses + LangGraph's async execution handle the latency budget (≤90s end-to-end). Extracting to a worker becomes a clean refactor post-demo if needed.
**Alternatives considered:** Celery worker + Redis queue (rejected: adds a 6th service, unnecessary for single-machine demo); separate orchestrator container (rejected: doubles deploy complexity for no demo benefit).
**Date:** 2026-04-26
**Status:** accepted

### ADR-003 — Tier 0 ships 3 channels (LinkedIn, Email, Paid Search) — not 6
**Decision:** Cap parallel channel fan-out at 3 channels for Tier 0. The 6-channel design (LinkedIn, Email, Paid Search, Landing Page, Event Page, SDR Outreach) remains in seeds and is consumable via the same Channel Specialist agent — but the demo flow uses 3.
**Why:** Latency budget (≤90s end-to-end) is tight; 3 parallel LLM calls hit ~6s, 6 parallel calls risk Azure rate-limit thrash on demo day. 3 channels also keeps the plan visually scannable in the UI.
**Alternatives considered:** Fixed 6 (rejected: latency + rate-limit risk); user-selectable channel count (rejected: scope creep, decision fatigue).
**Date:** 2026-04-26
**Status:** accepted

### ADR-004 — Tier 0 D3 = terminology + CTA only (full D3 deferred)
**Decision:** W3 (multi-channel consistency) ships with terminology clustering (HDBSCAN over embeddings) + CTA scanning (regex+LLM) + canonical resolver. Tone drift, audience framing, and the full report composer with all 4 finding types are Tier 2.
**Why:** Tone drift requires fingerprint quality bar that's risky to hit in 5 days. Audience framing is an LLM call with no deterministic ground truth. Terminology + CTA give the cinematic "AI-powered (3) vs AI-assisted (2) — canonical is AI-assisted" demo moment with high reliability.
**Alternatives considered:** Skip W3 entirely (rejected: kills the platform-not-feature narrative); ship full D3 (rejected: time + reliability risk).
**Date:** 2026-04-26
**Status:** accepted

### ADR-005 — Eval harness baked in from P2 (not P9)
**Decision:** `eval/runner.py` skeleton + `eval/golden_set.py` loader land in P2 alongside the LLM gateway. Metrics implementation (gap-catch rate, plan-completeness) lands in P9 but the harness exists from day 2.
**Why:** Regression detection must be cheap from the moment the first agent runs. If we wait until P9, prompt regressions during P3–P8 are invisible. Bake the harness in, populate metrics later.
**Alternatives considered:** Keep eval in P9 only (rejected: blind to mid-build regressions); land full eval in P2 (rejected: unnecessary overhead before there are agents to evaluate).
**Date:** 2026-04-26
**Status:** accepted

### ADR-008 — Override apply: list/object-typed paths route to mandatory_inclusions audit
**Decision:** Any free-text override whose `field_path` targets a list/dict/tuple/set-typed top-level Brief field (`quantified_targets`, `success_metrics`, etc.) is routed to `constraints.mandatory_inclusions` as `[override:{path}] {value}` audit line. The API endpoint `POST /briefs/{id}/overrides` wraps `apply_overrides_to_brief` and any residual `ValidationError` is returned as a structured 422 (never 500).
**Why:** The Clarifier sometimes emits paths like `quantified_targets` when asking about a metric/baseline/target. The user's free-text answer cannot validly populate `list[QuantifiedTarget]` — `Brief.model_validate` raises `list_type` and the entire override apply 500'd. Routing those to the audit bucket preserves the answer (audit row + the bucket entry), keeps the Brief shape valid, and lets the rest of the user's overrides apply. The 422-not-500 envelope means a flaky override never breaks the demo flow with an opaque error.
**Alternatives considered:** Rejecting the override with 400 (rejected: silently throws away the user's answer); auto-parsing the free-text into a `QuantifiedTarget` (rejected: requires another LLM call mid-form-submit and inflates demo latency); hardening the Clarifier prompt to never emit list-typed paths (rejected: defense-in-depth still requires server-side coercion since prompts drift).
**Date:** 2026-04-30
**Status:** accepted

### ADR-007 — Axion demo theme (deep navy + electric coral gradient)
**Decision:** Custom Streamlit theme (`ui/.streamlit/config.toml`) plus injected global CSS (`ui/styles.py`). Palette: bg `#0F1623` / panel `#172033` / soft `#1F2A40` / text `#E6ECF3` / accent `#FF6B5B` (coral) / accent-2 `#FFA94D` / success `#2BD68A` / warning `#F2C94C` / danger `#FF5C7A` / info `#6FB3F2`. Gradient hero banners (coral → orange → blue) via `render_banner`. Severity pills via `severity_pill`. All API failures funnel through `styled_error` (no raw stack traces visible to judges).
**Why:** Default Streamlit light theme reads as a dev UI. A judge looking at this needs to see "production tooling" within the first 3 seconds. The dark canvas pushes contrast onto the data; the coral accent makes the active CTAs jump; the success/warning/danger palette mirrors the severity-emoji convention already in use across W1/W2/W3 reports. CSS is injected via a single `inject_global_css()` call so we don't ship a separate stylesheet asset (keeps the package portable for post-demo distribution).
**Alternatives considered:** Streamlit's built-in dark mode (rejected: still visually generic, no brand identity); custom React component (rejected: build step, scope creep); Tailwind CDN injection (rejected: fights Streamlit's own CSS reset).
**Date:** 2026-04-29
**Status:** accepted

### ADR-006 — Greedy cosine clustering replaces HDBSCAN for Tier 0 W3 terminology
**Decision:** `agents/terminology_scanner.py:cluster_terms` uses greedy single-pass cosine-threshold clustering (τ=0.70) over Azure `text-embedding-3-small-alpha` vectors instead of HDBSCAN. The API surface is preserved so swapping back to HDBSCAN later is a one-file change.
**Why:** No native-build risk on Windows/WSL hackathon machines (HDBSCAN's numpy/scipy build chain has bitten us on Windows before); deterministic on the demo asset set; the plan's own fallback already authorizes pairwise-similarity for `len(assets) < 3`. Threshold 0.70 was chosen empirically: live cosine values on the small embedding model are AI-powered ↔ AI-assisted = 0.7515, book-a-demo ↔ schedule-a-call = 0.6172, all unrelated pairs ≤ 0.41 — 0.70 cleanly catches the headline drift case while keeping unrelated terms in their own clusters. Plus a deterministic fallback (each term = own cluster) when embeddings throttle, so the W3 demo stays stable even on a flaky network.
**Alternatives considered:** HDBSCAN (rejected: native build risk + asset sets are small enough that cluster-density math gains nothing); pairwise-only (rejected: greedy is faster than full O(n²) for 30 assets and produces the same answer for our threshold); LLM-based clustering (rejected: cost + latency + non-determinism for a problem cosine solves cleanly).
**Date:** 2026-04-29
**Status:** accepted

### ADR-010 — PDF (reportlab) + PPTX (python-pptx) replace JSON in the UI download row
**Decision:** The UI Export section on Plan from Brief surfaces three download buttons — **HTML** (the existing Gantt timeline export), **PDF**, and **PPTX**. JSON and Markdown remain on the API surface (`GET /plans/{id}/export/{json,markdown}`) for tooling but are not exposed to the Streamlit user. The PDF generator is `export/pdf_exporter.py:export_plan_pdf` (reportlab Platypus, pure Python). The PPTX generator is `export/pptx_exporter.py:export_plan_pptx` (python-pptx, pure Python). Both reuse the `ExecutionPlan` + `copy_drafts` shape that markdown/PDF already consumed; both render with the brand palette (indigo `#4F46E5` accent on near-white canvas, slate-900 text). The PPTX deck is 16:9 widescreen with: title slide (split-layout — indigo block + campaign name + status pill), Audience & Objectives, one slide per channel (meta card + copy preview), Timeline, QA & Success Metrics, closing slide. Every slide carries an indigo brand strip with the `Lumeo | Campaign Studio` wordmark.
**Why:** Marketers want a shareable artifact, not a JSON dump. PDF gives the on-paper plan; PPTX gives a stakeholder deck without manual reformatting. Both libraries are pure Python (no system deps), so the deploy surface stays small. Mirroring the markdown structure means we don't have to maintain a separate plan model — the same data flow lights up three formats.
**Alternatives considered:** **weasyprint for PDF** (rejected: requires Pango / Cairo / GLib system libraries; one more apt-install for every fresh dev box). **xhtml2pdf** (rejected: weaker HTML/CSS support, output looks dated). **wkhtmltopdf via pdfkit** (rejected: external binary dep + license uncertainty). **Generate Markdown then convert to PDF/PPTX downstream** (rejected: every conversion step is a fidelity risk and requires another tool — direct generation is cleaner). **Single PDF button only** (rejected: stakeholders specifically want decks; PDFs don't open as editable slides).
**Date:** 2026-05-04
**Status:** accepted

### P12 UX polish + new export formats (2026-05-04)
- **Collapsible gap + finding cards.** Switched from static `<div class='gap-card …'>` blocks to native `<details class='gap-card gap-hard'>` with a `<summary>` row carrying the severity pill + field path; the body sits in `<div class='gap-card-body'>`. CSS hides the default disclosure marker (`summary::-webkit-details-marker { display: none }` + `list-style: none`) and adds a rotating `›` (CSS unicode escape `\203A`) chevron via `::after` that flips to `-90deg` on `[open]`. Hard gaps + blocker / error findings are **not** auto-opened anymore (user feedback on round 4: all findings should start collapsed; the metric strip already shows the headline counts). Severity color preserved through class composition — the existing `.gap-card.gap-hard` / `.finding-card.finding-blocker` palette rules still apply since the wrapping element still wears those classes.
- **Copy preview iframe.** The previous `<pre class='lumeo-copy-pre'>` rendered via `st.markdown(unsafe_allow_html=True)` but Streamlit's HTML sanitizer strips `onclick` handlers, so a real Copy button wasn't possible at the page level. New approach: each channel's preview is a self-contained `streamlit.components.v1.html(html, height=320)` iframe with inline CSS, the formatted body, a hidden `<textarea id='raw-text'>` carrying the plain text, and a `<button class='copy-btn'>` whose JS uses `navigator.clipboard.writeText(rawJson)` first, falling back to `document.execCommand('copy')` on the textarea if clipboard API is blocked. Multiple previews coexist because each lives in its own iframe (no DOM id collisions). Helper at `ui/pages/1_Plan_from_Brief.py:_render_copy_preview(channel_name, body)`. Format detection regex (`_COPY_LABEL_RE`) catches `Subject:`, `Preheader:`, `Touch N:`, `For X:`, `CTA:`, `Follow-up N:`, `Day N:` — those lines render with bold accent-colored labels; everything else becomes a paragraph. The indigo left strip on `.lumeo-copy-frame` was removed.
- **Brief QA replaces Plan QA.** New page `ui/pages/2_Brief_QA.py` is paste-only — the right-column plan-content textarea is gone. Flow: paste brief → `POST /briefs/intake` → `POST /briefs/{id}/analyze` → render `brief_to_rows` table + collapsible gap list → "Open in Plan from Brief" button stashes `raw_text` in session_state and calls `st.switch_page("pages/1_Plan_from_Brief.py")`. The cross-audit `brief_plan_relationship` capability remains on the API (`POST /qa/by_ids`) for tooling, just not surfaced in the Streamlit UI. Old `2_Plan_QA.py` deleted; `Home.py` + `0_Get_Started.py` references updated.
- **Asset Consistency frame transparent.** `.asset-card-frame` was a full white card behind each slot's inputs; user feedback was the boxed look competed with the white input fields below. Now: `background: transparent; border: none; border-bottom: 1px dashed var(--border-subtle)` so the only visual divider between slots is a thin dashed line. The slot label moved from a full-width letter-spaced header band to an inline `.asset-card-pill` chip (indigo on accent-soft, ~70px wide).

Falls back to direct YAML read if the stash is missing (covers tests + raw-URL navigation). Both `_launch_demo` and `_demo_d_assets` are cleared once consumed.
- **Card B paragraph-form brief.** Card A on Get Started loads the structured `seeds/golden_set/brief_002.md`; card B was loading the structured `seeds/exemplar_briefs/b2b_saas_q3_enterprise.md`. User wanted the SAME content as a single paragraph of prose so users see the textarea accepts free-flowing text. Solution: hardcoded `_DEMO_B_PARAGRAPH` constant in `1_Plan_from_Brief.py` carrying the same campaign content (objective, audience, channels, budget unspecified, timeline, success metrics, brand constraints) as one continuous block. Card A unchanged. Card C (Brief QA) unchanged.

The Run History dropdown was previously showing `$0.0000`; now it's accurate.

### LLM Gateway
- Structured outputs use `response_format={"type":"json_schema", "json_schema":{strict:True}}`. Strict mode requires `additionalProperties:false` on every object and `required` listing all properties; `core/llm/structured.py:_strictify` walks the Pydantic-emitted schema and enforces both before sending. Pydantic v2 emits `$defs` for nested models — the walker recurses into both `$defs` and `definitions`.
- Cache key is `sha256(prompt_name + prompt_version + variables_json + schema_name)`. **Bumping the prompt to v2 invalidates all v1 cache entries automatically** — no manual flush needed.
- Repair path: on first `ValidationError`, the gateway re-renders the prompt with a "your previous response failed schema validation: …" addendum and retries once at temperature 0. Two consecutive parse failures raise `StructuredOutputParseError`. Both failures are traced + costed.
- Tenacity retry covers `TimeoutError` and `ConnectionError` only — auth and 4xx errors fail fast.
- `_try_add_cost` re-raises `BudgetExceeded` (callers must know) but swallows Redis errors so a Redis hiccup doesn't kill a paid Azure call.

### Azure Structured Outputs strict-mode `required`
- Pydantic only lists truly-required fields in `required`. Azure strict-mode (`json_schema` + `strict:true`) demands every property be listed — failing requests with `"'required' is required to be supplied and to be an array including every key in properties"`. `core/llm/structured.py:_strictify` overwrites `required` to include all properties on every object node.
- **Consequence (important).** Once every field is `required`, the LLM is forced to emit every field — including server-generated fields like `id: UUID = default_factory=uuid4` and `created_at: datetime = default_factory`. Azure's structured-output engine cannot invent a UUID or datetime, so it emits `null`, which then 400s on Pydantic's UUID/datetime types.
- **Pattern: split persistence schemas from extraction schemas.** Persistence schemas (`Brief`, `Gap`, `GapList`, etc.) keep their UUID/datetime fields with `default_factory`. Their LLM-facing twins (`BriefExtraction`, `GapExtraction`, `GapListExtraction`) drop those server-generated fields entirely. Agents bind `call_structured(output_schema=XxxExtraction)`, then promote with `extraction.to_brief()` / `extraction.to_gaps()` — server fills `id`/`created_at` locally. Apply this pattern to any new schema that has auto-generated fields and is bound to an LLM output.

## Conventions

> How to use this file consistently across sessions.

1. **Update after every meaningful change.** New ADR, new blocker, blocker resolved, phase complete, assumption verified — log it.
2. **Timestamp everything in ISO format** (`YYYY-MM-DD`).
3. **Number ADRs sequentially** (ADR-001, ADR-002, …). Never reuse a number, even for superseded decisions.
4. **Tag blockers with status** (open / resolved / wontfix) — never leave undefined.
5. **Snapshot section is 3 sentences max.** If it's longer, you're putting detail in the wrong place.
6. **Stack & Infrastructure section is the single source of truth** for what's deployed. Code drift from this section is a bug, not a flexibility.
7. **Verify before recommending from memory.** A memory naming a function is a claim that it existed *when written*. Grep for it before suggesting.
8. **Do not delete entries.** If something is wrong, append a correction with a new timestamp. The history matters.
